## 2. Грани, модели, предобработка

- **Эмбеддеры:**
  - `BAAI/bge-small-en-v1.5` @ `5c38ec7c` (основная, вход до 512 токенов);
  - `sentence-transformers/all-MiniLM-L6-v2` @ `1110a243` (контроль, вход до 256).

  Считались на GPU (RTX 3060 Laptop, torch 2.11 + cu128).
- **Грани узла:**
  - F0 — текст реплики;
  - F1 — саммари, F2 — сущности (обе от LLM);
  - F3 — предыдущая и следующая реплика той же сессии, каждая до 128 токенов;
  - B2 — один эмбеддинг склейки F1 + F2 + F0 + F3.
- **Доли обрезанных входов:**

  | | F0 | F3 (сосед > 128 токенов) | F3 целиком | B2 |
  |---|---|---|---|---|
  | bge (512) | 16.5 % | 45.6 % | 0.006 % | 27.3 % |
  | MiniLM (256) | 34.4 % | 45.6 % | 34.5 % | **84.5 %** |

  У MiniLM склейка B2 почти всегда обрезана: бейзлайн B2 на MiniLM заведомо слабее.
- **Предобработка:** центрирование средним dev-корпуса → PCA 384 → 128 на dev-корпусе (абляция — гауссова проекция) → L2.
  - Выборка для обучения: 20 000 случайных узлов × 4 грани.
  - **Оговорка:** dev-haystack и test-haystack частично пересекаются по текстам (20 949 общих). Центрирование и PCA, обученные на dev, при оценке test будут трансдуктивными — без меток.
- **Подпространства:** QR в float64, затем fp32.
  - max ‖YᵀY − I‖_F = 1.4e-6 (порог 1e-5).
  - Вырожденных узлов 554 из 66 686 (0.83 %), все — с совпадающими гранями: 255 — сбой LLM (F1 = F2 = F0), 240 — короткие реплики, у которых саммари дословно равно тексту, 21 — реплики без соседей (F3 = F0).

## 3. Генерация F1/F2 и её стоимость

- **Модель и режим:** `claude-haiku-5-5`, промпт `f12-v1` (`llm_f12.py`), thinking выключен, effort `low`, JSON-схема `{summary, entities}`.
  - **Отступление от ТЗ:** temperature задать нельзя (API отвечает 400). Воспроизводимость — через дисковый кэш.
- **Пилот:** 500 реплик (стратифицированы по роли и квартилям длины), прямые вызовы, 96 с, **$0.069**.
- **Остальные реплики dev:** 67 427 через Message Batches (4 батча), примерно за 25 мин, **$4.627**.
- **Итого dev:**

  | Вызовов | Входных токенов | Выходных токенов | Потрачено |
  |---|---|---|---|
  | 67 927 | 47.86M (в среднем 705) | 9.07M (в среднем 134) | **$4.70** |

- **Сбои:** 268 вызовов (0.39 %, невалидный JSON или пустой ответ). Для них F1 = F2 = F0, одинаково для всех методов; это 0.39 % узлов dev.
- **Прогноз test:** 121 550 новых текстов, средние токены dev по слоям «роль × длина», батч-цена → **$8.30**.
  - Остаток кредита после dev: $7.17 − $4.70 = **$2.47**.
  - **Для test нужно пополнение примерно на $6.** По решению от 21.11 test не запускается.

## 5. G1 против сильнейшего из B2–B5 (turn recall_any@5, парно по 135 вопросам)

| Модель, d | Лучший бейзлайн | G1 | Бейзлайн | Разница, п.п. | 95 % CI (bootstrap 10k) | McNemar: только бейзлайн / только G1, p |
|---|---|---|---|---|---|---|
| bge, 128 | B4 | 87.4 | 87.4 | 0.0 | [−5.2, +5.2] | 6 / 6, p = 1.0 |
| bge, 384 | B5 | 90.4 | 88.9 | +1.5 | [−2.2, +5.9] | 3 / 5, p = 0.73 |
| MiniLM, 128 | B4 | 87.4 | 86.7 | +0.7 | [0.0, +2.2] | 0 / 1, p = 1.0 |
| MiniLM, 384 | B4 | 88.9 | 87.4 | +1.5 | [0.0, +3.7] | 0 / 2, p = 0.50 |

**Предварительный исход на dev — «Б. Неразличимо»:**
- 95 % CI содержит 0 во всех четырёх случаях;
- ни одна разница не достигает +3 п.п.;
- G1 нигде не хуже лучшего бейзлайна.

Это не решение ТЗ — решение будет по test. **Мощность:** при 135 вопросах полуширина CI 2–5 п.п. На test (335 вопросов без `_abs`) она будет примерно в 1.6 раза уже, около ±2–3 п.п. Эффект +3 п.п. тогда различим только в верхней части оценок.

**Что видно уже на dev:**
- **«Больше информации» в одном векторе не помогает.** На bge B2 (склейка в один эмбеддинг) хуже F0 в одиночку: 77.8 / 82.2 % против 81.5 / 83.7 %. На MiniLM B2 чуть лучше B1 (76.3 / 77.8 против 74.1 / 80.0), но 84.5 % склеек там обрезаны. Многовекторные B3/B4/B5 и G1 дают +4…+7 п.п. к B1 на bge и +4…+13 п.п. на MiniLM.
- **Выигрыш даёт многовекторность, а не геометрия.** G1 ≈ B4 ≈ B5 в пределах шума.
- **На уровне сессий у всех методов 97–99 %** — потолок, как и предупреждало ТЗ.
